# ゲーム内部の処理 (妖怪ウォッチ4 v2.2.0)

アドレスは v2.2.0 の `main` NSO を展開したイメージ上のオフセット。

## タグの構成 (NTAG213)

| ページ | 内容 |
|---|---|
| 0〜2 | UID / BCC / ロック |
| 3 | `E1 11 12 0F` (NDEF の Capability Container) |
| 4〜26 | NDEF: `https://www.ywg.jp/<トークン>` (トークンの先頭 3 文字 = 種別 ID) |
| 27 | `BA B0 01 01` |
| 28〜39 | 暗号化データ 48 バイト (AES-128-CTR) |
| 40〜42 | 設定 (AUTH0 = `0x1C`、ACCESS = `0x80` で読み出しも保護) |
| 43 / 44 | PWD / PACK (`BE EF`) |

### 平文 (ページ 28〜39 を復号したもの)

```
30 33 31 35 4D 43 4E 00 00 00 00 00 00 00 00 A7   "0315MCN" + 0 埋め + チェックサム
00 x 16
00 x 16
```

- 先頭 4 文字 (`0315`): シールの番号 (`A315`)。`int(種別 ID, 36) − 28652` と一致する
  (はむはむ `MCN` = 28967 → 315、ホノボーノ `MD2` = 28982 → 330)。ゲームは使っていない
- 5〜7 文字目 (`MCN`): 種別 ID (36 進 3 文字)。ゲームはこれでアークの種類を決める
- 各 16 バイトブロックの最後のバイトは、先頭 15 バイトの和 (mod 256)
- ブロック 2 の先頭バイトが 0 以外だと、追加の抽選が行われる (おまけと思われる。実物は 0)

## 読み取りの流れ

読み取りはステートマシン (関数表 `0x14c33c8`) で進む。

| 関数 | 処理 |
|---|---|
| `0x7244a0` | ページ 0x00〜0x1B を FAST_READ (パスワードなし) |
| `0x724550` | UID から PWD / AES 鍵 / IV を算出 → PWD_AUTH → ページ 0x1C〜0x2A を FAST_READ |
| `0x724850` | ページ 28〜39 を `nn::crypto::DecryptAes128Ctr` で復号し、ブロックごとのチェックサムを確認 |
| `0x724ae0` | 種別 ID を 36 進数として読み (`strtoul(..., 36)`)、種別表を検索。使用済み UID リストと照合 |
| `0x724e30` 〜 | 抽選 |

- PWD_AUTH の送信は `0x9597d8` (`nn::nfc::SendCommandByPassThrough`)。送信順は `1B h2[28] h2[29] h2[30] h2[31]`。
  応答の 2 バイトを `BE EF` と比較する
- 使っている生コマンドは PWD_AUTH (0x1B)、FAST_READ (0x3A)、WRITE (0xA2) だけ。
  READ_SIG (0x3C) は送らないので、NXP の署名は確認していない
- 読んだページ 0〜27 (NDEF の URL) は参照していない。アーク読み取りでタグへの書き込みもしない

実機で確認したこと: UID を変えて作り直したアーク (URL と署名は元のまま) も、種別 ID を変えたアークも、正しく読み込まれる。

### 主な定数

| アドレス | 内容 |
|---|---|
| `0x1299977` / `0x1299982` | HMAC 鍵 `DKtjn3JAZc` / `5g9D63n8Mt` |
| `0x1257c20` | ニブル置換表 (`(元, 置換後)` の 16 ペア) |

## 種別表

RomFS の `data/common/gamedata.cpk` 内 `gamedata/nfc/nfc_lottery_config.cfg.bin` の `NFC_INFO`
(v2.2.0 で 506 件、v1.0 では 218 件)。1 件 18 個の int (0x48 バイト)。

| フィールド | 内容 |
|---|---|
| [0] [1] | 種別 ID の数値 (min / max。すべて同じ値) |
| [2] | 抽選テーブル ID |
| [4] | 妖怪 (chara_base のハッシュ。妖怪付きは 79 件 → [YOKAI_IDS.md](YOKAI_IDS.md)) |
| [5] [8] [9] | 追加の抽選テーブル ID |
| [6] | 限定報酬のテーブル (ゴッド魂・魔神のアーク・装備など) |
| [10] | アイテム |
| [12] [16] | ゲームフラグ |
| [17] | 使用済み UID リストの選択 |

### 使用済み UID

種別判定を通ると、UID がセーブデータ内のリストに記録される。

- [17] = 0: 1000 件のリスト。同じ UID は二度と使えない (「このアークは一度しか読み取れません」)
- [17] ≠ 0: 300 件の別リスト。1 日 1 回 (「このアーク・妖聖剣の読み込みは 1 日 1 回までです」)

### エラー

ゲームは `0x16xx` の形でエラーを持ち、下位バイトがスクリプト (`nfc_menu_4.00.11.lua.bin` の `DispErrorMessage`) に渡る。

| コード | 原因 | 表示 |
|---|---|---|
| `0x1611` | 復号後のチェックサム NG | |
| `0x1612` | 種別 ID が 0 | |
| `0x1613` | 永久リストに UID がある | このアークは一度しか読み取れません |
| `0x1614` | 1 日リストに UID がある | 読み込みは 1 日 1 回までです |
| `0x1615` | 種別 ID が種別表に無い | 対応していないアークです。最新バージョンに更新して… |

### 抽選

抽選テーブルは `NFC_LOTTERY_INFO` の 7 つのカテゴリに分かれていて、同じテーブル ID でもカテゴリごとに中身が違う
(けいけんちだま・こけし、封魔のアーク、コイン、食べ物など)。1 回の読み込みでどのカテゴリから何回引くか、
限定報酬 ([6]) が出る条件は解析していない。種別 ID を書き換えて作ったアークでは、限定報酬付きの種別でも普通の抽選になった。

## データ形式のメモ

- RomFS の中身はほぼ CRI CPK (暗号化なし、@UTF テーブル + CRILAYLA 圧縮) → `work/cpk.py`
- 設定ファイルは Level-5 の cfg.bin (エントリ = crc32(名前) + 型付きの値、末尾にキー名表) → `work/cfgbin.py`
- 名前は `text/ja/*_text.cfg.bin` の `NOUN_INFO` をハッシュで引く
- スクリプトは Lua 5.2 バイトコード → `work/luadis.py`
